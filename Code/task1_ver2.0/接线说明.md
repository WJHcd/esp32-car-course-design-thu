# task1 接线说明（ESP32-S3 ↔ 红外循迹 + 超声波）

> 任务一：把参考 STM32 程序（Car_main.c）拆成 **红外检测 / 超声检测 / 行走策略** 三个模块，
> 在 ESP32-S3 上实现"循迹 + 超声波避障"。电机接线沿用 `motor-drive-test`（已在车上接好）。

---

## 1. 本任务新增接线（相对 motor-drive-test 多出 6 根）

### 四路红外循迹 LQ-R4CHV（数字量，OUT1~OUT4）

| LQ-R4CHV 引脚 | ESP32-S3 GPIO | 对应 a/b/c/d |
| --- | --- | --- |
| OUT1 | **GPIO18** | → d |
| OUT2 | **GPIO21** | → c |
| OUT3 | **GPIO41** | → b |
| OUT4 | **GPIO42** | → a |
| VCC | 3V3（或 5V，看模块丝印） | — |
| GND | GND | — |

> ⚠️ 红外 OUT1~OUT4 用 GPIO18/21/41/42（**避开 GPIO19/20 = 原生 USB 数据脚**，否则电脑认不出 ESP32）。
> a/b/c/d 映射（2026-08-25 修正）：**a=OUT4, b=OUT3, c=OUT2, d=OUT1**（a/b 一侧、c/d 另一侧）。
> 极性（2026-08-25 实测修正）：本模块**黑线=低电平、白底=高电平**（常规极性），`IR_LINE_LEVEL=0`。

### HC-SR04 超声波（TRIG / ECHO）

| HC-SR04 引脚 | ESP32-S3 GPIO | 说明 |
| --- | --- | --- |
| TRIG | **GPIO39** | 触发，发 10µs 高电平 |
| ECHO | **GPIO40** | 回波，高电平宽度=距离；经分压/电平转换后接入 |
| VCC | 5V | HC-SR04 需要 5V |
| GND | GND | 共地 |

> ⚠️ TRIG/ECHO 用 JTAG 脚 GPIO39/40（本任务不做 JTAG 调试，可当普通 GPIO）。经典 HC-SR04 在 5V 供电时 ECHO 可能接近 5V；ESP32-S3 GPIO 不应直接承受 5V，必须实测并通过电阻分压或电平转换限制到 3.3V。

## 2. 上电顺序

1. 先接好全部信号线 + GND 共地
2. ESP32-S3 用 **USB 供电**（插电脑，方便 `idf.py monitor`）
3. D24A 电机板与红外/超声波模块用电池供电（电机母线 Vin+ / Vin-）
4. 上电顺序：先 USB，后电池

> 只测红外/超声波时不必给 D24A 供电；跑行走策略/综合模式才需要。

## 3. 运行模式切换（main.c 顶部 `TASK1_MODE`）

| 值 | 模式 | 说明 | 需要供电 |
| --- | --- | --- | --- |
| 0 | 综合模式 | 循迹 + 超声波避障，正式跑车 | USB + 电池 |
| 1 | 红外检测测试 | 串口打印 OUT1~4 / a b c d | USB（+红外模块电源） |
| 2 | 超声检测测试 | 串口打印距离 | USB（+模块电源） |
| 3 | 行走策略自检 | 喂合成数据跑状态机，**不驱动电机** | USB（无需电池） |
| 4 | **仅红外巡线测试** | 驱动电机真实循迹；**不初始化、不读取超声波，避障禁用** | USB + 电池（红外模块供电） |
| 5 | **平移方向自检** | 架空轮子观察左移/右移/前进方向，用于平移标定 | USB + 电池（可只供 D24A） |

改完 `#define TASK1_MODE x` 后重新编译烧录即可。

## 6. 待标定项（第一次上电时）

1. ✅ **红外极性**：已实测为黑线低、白底高；算法统一转换为 `1=黑线、0=白底`
2. **左右顺序**：当前定义 `a(左外)=OUT4, b=OUT3, c=OUT2, d(右外)=OUT1`，仍需按车头方向核对
3. ✅ **轮位与电机方向**：实车已确认 `A=左轮、C=右轮、B=后轮`；A/B/C 三路均为“逆时针=正”，故 `walking.c` 中为 `L=A、R=C、B=B`，`s_motor_sign[]={+1,+1,+1}` 无需翻转。中心线实测旧组合会后退，现已把前进分量校正为 `A 反、C 正、B 停`；后续循迹实测又确认 B 的转向分量需反向，`TURN_SIGN_B=-1`。C 轮略快，当前输出系数为 0.90。
4. **修正方向**：黑线在右侧时若车辆反向修正，只翻转 `STEERING_SIGN`
5. **循迹参数**：低速架空确认后再调 `LINE_KP/LINE_KD` 与 `LINE_BASE_SPEED_PCT`
6. **平移方向**：用 `TASK1_MODE=5` **着地**短脉冲确认左/右平移与前进方向（勿架空，架空分不清平移/旋转）；左移脉冲走反 → 翻转 `walking.c` 顶部 `STRAFE_SIGN_L/R`；原地旋转 → 翻转 `STRAFE_SIGN_B`
7. **避障时序/速度**：`AVOID_STRAFE_LEFT_MS / AVOID_FORWARD_MS / AVOID_STRAFE_RIGHT_MS` 与速度参数，结合赛道和障碍尺寸标定（保持左/右平移时长 > 前进时长）

### 6.1 低速测试参数（`walking.c` 顶部）

当前默认是 `TASK1_MODE=4` 的仅红外巡线版。它采用急弯保护标定：正常循迹基准速度为 `12%`、最低速度为 `8%`、最大转向量为 `10%`；检测到仅外侧红外命中时，自动改为 `7%` 前进并以不超过 `12%` 的转向量过弯。后轮 B 的转向增益为 `0.60`，该值已验证直角弯基本可过；普通循迹会对误差低通滤波、在中心附近设置死区，并且每 20ms 最多变化 `3%`，降低直线抖动。锐角入弯后若四路全白，立即停止前进并进入 `CORNER_SEARCH`，按最后一次原始红外确认的黑线侧原地低速转。仅外侧探头的一次黑线不算出口；必须有内侧探头连续命中 3 拍才恢复巡线，因此不易在转错方向时把来路线当成出口。若首选方向 `LINE_CORNER_RETRY_MS=1000u` 内仍未得到可信出口，程序才反向尝试一次；计时**不会**结束转弯，结束条件仍是确认重新见线。普通 `LINE_SEARCH` 首次见线也不再刹车，而是持续原地转到连续两拍确认。`LINE_SEARCH_TIMEOUT_MS=0` 表示当前仅红外测试版持续找线；正式模式如需故障保护，可设为正毫秒数。这样找线方向不受直线防抖滤波/死区归零影响。速度仍偏快时，优先小步降低 `LINE_BASE_SPEED_PCT` 和 `LINE_MAX_TURN_PCT`；电机低于约 `8%~10%` 可能因静摩擦而不动，不能一味降低。
