# 黑色终点检测与现场验收

本轮把推球终点从绿色改为约 10cm 的实心黑色方块。只修改目标识别及文字说明，
不改变摄像头巡线、避障、电机、云台和推球动作参数。黑色终点仍显示紫色框。

黑色和场内巡线、场外桌椅没有颜色差异，因此程序不会采用“看到黑色就算终点”。
一个候选必须依次满足：

1. 灰度不高于 `BALL_MARKER_BLACK_GRAY_MAX`，且每个 4x4 网格至少半数像素为黑；
2. 连通域至少 2x2 格，接近实心方块，不细长、不过大、不触碰画面边缘；
3. 包围盒外环多数为浅色地面；
4. 同一帧至少有红球或蓝球，终点在图像中位于球的上方或只略低；
5. 大目标连续 3 帧、小目标连续 4 帧才输出，丢一帧后重新确认。

这几层分别针对单点噪声、黑色巡线/L/T 拐角、大块或触边桌椅、场外背景以及
瞬态误识别。底部 30% 车体屏蔽继续生效。原始黑候选先保留 16 个，再做形状
过滤，避免大黑线占满候选数组后把终点挤掉。

主要参数均在 `main/ball_detect.h`：

- `BALL_MARKER_BLACK_GRAY_MAX=105`：黑色像素阈值；漏检实物黑块时逐步加到
  110/115，但不要超过巡线阈值 120。普通阴影误检则向 95/90 降。
- `BALL_MARKER_FILL_MIN=0.55`、`BALL_MARKER_ASPECT_MAX=3.0`：实心度和最大宽高比。
- `BALL_MARKER_SURROUND_GRAY_MIN=155`、`BALL_MARKER_SURROUND_LIGHT_PCT=55`：
  白地包围条件。地板较暗导致漏检时，优先降低前者到 145，再看串口结果。
- `BALL_MARKER_NEW_TRACK_Y_MIN/MAX=0.12/0.60`：新目标中心只在原图 12%～60%
  高度建立；确认后可继续跟到 70% 检测边界。

先使用 MODE9，将一个球和一个黑终点同时放入视野，分别测试近、中、远距离，
再将巡线、黑色桌椅逐个放入画面。真终点应在连续约 3～4 个处理帧后出现紫框；
没有球时即使终点存在也不会出框，这是有意的安全策略。通过后再切 MODE8。

串口诊断中：`M` 表示像素/网格级黑候选，不代表最终通过；`shape` 是形状拒绝，
`surround` 是白地包围拒绝，`geometry` 是无球或前后关系拒绝，`confirmed` 才是
控制状态机收到的终点数。若真终点不出框，根据这几个计数判断是哪一层拦截。

主机合成回归（不依赖 ESP-IDF、不烧录）：

```sh
cc -std=c11 -I main tests/test_black_marker.c main/ball_detect.c -lm -o test_black_marker
./test_black_marker
```

算法能屏蔽典型线段、拐角、触边/过大黑块，但无法仅凭单目 RGB 图像百分之百
区分“外观、大小、形状、位置都与终点相同”的远处黑色椅脚。若现场仍有这种
特例，应提供未叠框的原始相机帧，再增加固定场地 ROI 或为终点改用唯一图案。
