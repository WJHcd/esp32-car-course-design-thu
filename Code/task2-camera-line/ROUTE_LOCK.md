# 路线锁定与避障调试（2026-09-08）

适用图片路线：起点向上 → 右锐角 → 斜线及左缓弯 → 左直角 → 左直角 →
右直角 → 接近木板 → 左移/前进/右移接线 → T 横杆 → 推球。
MODE 0；球识别和 ball_task 的行为代码未改。

## 摄像头触发，顺序只是辅助

`walking.c` 的 `s_route_turns={+1,-1,-1,+1}` 只表示四个大弯方向，
不包含距离、定时转角，也不把斜线末端缓弯单独计为大弯。
两张不同新帧在同侧呈现大误差时锁定视觉方向；如果此方向与路线表不符，
打印 `route hint mismatch`，本次启动后关闭顺序辅助，之后按视觉锁向。
只有缺少明确方向的丢线恢复才使用当前路线提示。

同一弯锁定后不能被后续误差反号覆盖。失线立刻停止前进，原地沿锁定方向找线；
经历失线后，同侧或中央的非宽黑候选先停车，下一张新帧确认后执行原有出口助推。
重新进入 RUN、连续三张新帧误差绝对值 ≤0.25 才解除方向锁。
只有该弯经历过失线且顺序辅助仍有效才推进路线索引；未失线的缓弯不消费索引。
此设计不能保证所有复杂线型都正确编号；连续图像与提示冲突时退回视觉，
避免把错误编号当成绝对路线。单一扫描带也不能绝对分辨入口/出口/旁线。

巡线按每张新图更新滤波/微分，不再按20ms重复消耗旧图，也不等待 stable 才更新见线。
整合模式超过700ms没有新帧/结果过期就停车，恢复需新的 stable 帧。
路线找线/锁定弯超时5s进入 `ROUTE_HOLD`，不反向重启；摆正并复位后重新开始。
5s 是安全上限，不是完成角度的依据。图像时间戳仍为结果发布时间，未测出完整采集延迟。

## 横移执行

只在 RUN 连续三张新帧居中且无转弯锁时接受超声13cm、两个近距离样本触发。
一次启动只绕障一次，不会在 LINE_SEARCH 原地转动中接受超声触发。

左右横移起步使用18%车体横移指令240ms，然后恢复13%档。
18%是车体指令，B轮经混控后更高，不等于每轮18%。左移保留G=1.70及T=+0.5，
右移保留G=1.45；原先方向符号、C轮0.90校准增益、巡线/球任务的底层驱动保持。

每个完整的200ms编码器新采样窗口比较三轮原始脉冲，不使用显示低通RPM：
假定三轮型号/轮径/脉冲每轮圈一致，纯横移的理想比例是 A=C、B=A+C。
当三路各有至少2个脉冲时，C轮输出向A轮修正，B轮输出向A+C修正。
每次修正最多0.35个百分点，总修正限±2个百分点，只作用于避障横移。
这是有限轮速平衡，不是IMU偏航闭环，不能直接检测轮子打滑、装反或车身旋转。
若三轮PPR或轮径不同，先标定，不能盲用这一比例。

任一轮连续三次完整窗口零脉冲/轮速比例偏差超过65%，或启动1s后仍无新编码器采样，进入 `AVOID_HOLD`。
不能区分堵转和编码器断线，均停车，不反复大力顶着走。
左右平移日志含 `strafe pulses A=... B=... C=... trim B=... C=... stall=...`。
右移接线失败、绕障过程中摄像头中断也进入 `AVOID_HOLD`，不自动旋转找线。

编码器采样加互斥锁，避免TFT/球任务/行走同时读清PCNT导致重复计数或漏计；
里程清零时也清PCNT残留，避免前段脉冲混入后段。单相编码器不提供真实运动方向。

## 位置与交接限制

入弯和出弯没有增加固定行驶距离；绕障后右移到黑线中央由摄像头两帧确认。
左移/前进仍沿用原来的17cm/18cm参数除以估计10cm/s，实际是1.7s/1.8s开环时长。
这些不是实测位移。左移助推可能改变实际距离，必须着地复测。
现有窄扫描带不识别木板边缘，无法保证整车侧向/纵向净空；不能把“看见线”
冒充“车身已越过木板”。后段黑线位于入口线左侧，所以右移不应镜像左移距离。

绕障接回线后才武装T横杆：首候选帧停车、第二新帧确认 → T_HANDOFF停稳500ms
→ 调用现有ball_task_start，由原球任务抬云台和观察。取消1s定时入口。
车头相对T横杆的真实停车位置仍取决于摄像头俯角/扫描带位置，需实车核对。

## 参数和验证

重点参数均在walking.c：ROUTE_HINT_ENABLE、CORNER_ENTER_FRAMES、
CORNER_RELEASE_FRAMES、CORNER_RELEASE_ERR、LINE_CORNER_TIMEOUT_MS、
AVOID_STRAFE_LAUNCH_PCT/MS、AVOID_BALANCE_MAX_PCT、AVOID_BALANCE_STEP_PCT、
AVOID_STALL_CONFIRM、T_HANDOFF_DWELL_MS。恢复泛用视觉可设ROUTE_HINT_ENABLE=0。

测试不编译ESP固件、不烧录，用主机GCC编译实际walking.c/encoder.c并替代硬件API：

```powershell
gcc -std=c11 -Wall -Wextra -Werror -I tests/stubs -I main tests/test_walking_route.c -o "$env:TEMP/task2-route-test.exe" -lm
& "$env:TEMP/task2-route-test.exe"
gcc -std=c11 -Wall -Wextra -Werror -I tests/stubs -I main tests/test_encoder_motion.c -o "$env:TEMP/task2-encoder-test.exe" -lm
& "$env:TEMP/task2-encoder-test.exe"
```

覆盖四弯顺序、缓弯不推进、锁定中反号、旧帧不重复确认、丢线立即停止前进、
超时不反转、相机失联、避障门控、T交接、脉冲比例修正、停转/无采样保护和里程清零。
这些测试验证状态和计算，不能替代实车验证运动方向、横移净空或PWM力度。
