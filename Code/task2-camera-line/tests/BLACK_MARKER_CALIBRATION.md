# 黑色终点检测与现场验收

本轮把推球终点从绿色改为约 10cm 的实心黑色方块。只修改目标识别及文字说明，
不改变摄像头巡线、避障、电机、云台和推球动作参数。黑色终点仍显示紫色框。

黑色和场内巡线、场外桌椅没有颜色差异，因此程序不会采用“看到黑色就算终点”。
一个候选必须依次满足：

1. 灰度不高于 `BALL_MARKER_BLACK_GRAY_MAX`，且每个 4x4 网格有足够黑像素；
2. 连通域至少 2x2 格，接近实心方块，不细长、不过大、不触碰画面边缘；
3. 包围盒外环多数为浅色地面；
4. 有球时终点应位于球的上方或只略低；无球时允许独立显示识别框；
5. 大目标连续 2 帧、小目标连续 3 帧才输出，丢一帧后重新确认。

这几层分别针对单点噪声、黑色巡线/L/T 拐角、大块或触边桌椅、场外背景以及
瞬态误识别。底部 30% 车体屏蔽继续生效。原始黑候选先保留 16 个，再做形状
过滤，避免大黑线占满候选数组后把终点挤掉。

主要参数均在 `main/ball_detect.h`：

- `BALL_MARKER_BLACK_GRAY_MAX=115`：黑色像素阈值；仍不高于巡线阈值 120。
  普通阴影误检时再向 110/105 降。
- `BALL_MARKER_FILL_MIN=0.55`、`BALL_MARKER_ASPECT_MAX=3.0`：实心度和最大宽高比。
- `BALL_MARKER_SURROUND_GRAY_MIN=145`、`BALL_MARKER_SURROUND_LIGHT_PCT=40`：
  放宽后的白地包围条件，仍用于排除暗背景中的桌椅。
- `BALL_MARKER_NEW_TRACK_Y_MIN/MAX=0.05/0.69`：新目标中心可在屏幕所见画面的
  5%～69% 高度建立；确认后可继续跟到 70% 检测边界。

当前 TFT 显示方向与 JPEG 缓冲的 y 方向相反，`BALL_DETECT_FLIP_Y=1` 会让球和
终点识别统一使用屏幕所见坐标。显示屏仅画一条白色虚线，虚线以下才是被截掉的
底部 30% 车壳区域，虚线上方是有效检测区。该变换不修改摄像头巡线扫描带。

先使用 MODE9，单独放置黑终点测试近、中、远距离，再加入球、巡线和黑色桌椅。
真终点应在连续约 2～3 个处理帧后出现紫框。检测层允许无球时出框，但 MODE8
控制层仍然只有在当前球和终点同帧可用时才会下达运动指令。通过后再切 MODE8。

串口诊断中：`M` 表示像素/网格级黑候选，不代表最终通过；`shape` 是形状拒绝，
`surround` 是白地包围拒绝，`geometry` 是有球时前后关系不合理，`confirmed` 才是
控制状态机收到的终点数。若真终点不出框，根据这几个计数判断是哪一层拦截。

主机合成回归（不依赖 ESP-IDF、不烧录）：

```sh
cc -std=c11 -I main tests/test_black_marker.c main/ball_detect.c -lm -o test_black_marker
./test_black_marker
```

算法能屏蔽典型线段、拐角、触边/过大黑块，但无法仅凭单目 RGB 图像百分之百
区分“外观、大小、形状、位置都与终点相同”的远处黑色椅脚。若现场仍有这种
特例，应提供未叠框的原始相机帧，再增加固定场地 ROI 或为终点改用唯一图案。
