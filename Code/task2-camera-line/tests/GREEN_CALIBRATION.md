# 荧光浅绿终点检测修正

本轮只修改 ball_detect.c/h，不改变推球状态机、电机驱动、摄像头配置、接线、巡线和避障。

旧判据只要求 G 略高，RGB (120,126,120) 这样的偏绿银灰也能确认。
现在使用明显绿色与浅黄绿色双通道：明显绿色要求较高色度；浅黄绿色允许
较低色度但要求 G>R>B 且 R-B 足够大。不设亮度上限、不要求终点是深绿。
这些值是工程初值，不是本车实拍标定结果。银色如果反射绿色光后真的呈现
同样的 RGB，颜色算法仍无法可靠区分，必须结合原始图像设置车体遮罩。

参数在 main/ball_detect.h：

- BALL_GREEN_STRONG_CHROMA_PCT：明显绿色的色度门槛，默认 12%。
- BALL_GREEN_PALE_CHROMA_PCT：浅黄绿色色度门槛，默认 4%。
- BALL_GREEN_PALE_SPAN_MIN：浅黄绿 G-B 最小差，默认 8。
- BALL_MARKER_CELL_HIT_MIN：每个 4x4 网格至少 3 个有效绿色像素，避免单点假框。
- BALL_DETECT_Y_BOTTOM_PCT：原始图像底部 30% 不分类，显示图像不裁切。

同时修复：远端单行绿色块在达到 4 格时突然被拒绝；输出按累计轨迹寿命
排序导致旧假目标压住新真目标；失踪后直接继承旧确认资格。输出恢复按
当前面积排序，连续命中只作为确认条件，不再是累计优先权。

尚保留的限制：最多输出两个终点；新轨迹中心需位于图像上方 60%，
旧轨迹可跟到 70% 分类边界；这不是精确车壳遮罩。没有原始图像时不能
确认车壳是否伸到 60% 以上。局部对比度、目标身份和控制动作收敛不在本轮改动中。

先用 MODE9（静态检测）在近、中、远距离检查真终点是否稳定有框、银壳是否无框，
再用 MODE8 测试。小目标需连续 3 帧，大目标需 2 帧。若仍误检或漏检，提供同帧
未叠框的摄像头 RGB/JPEG，包含终点、地板和车壳，不能仅凭手机拍屏幕标定阈值。
若整张图普遍偏绿，还应检查照明和白平衡；不要在未核实前随意改相机参数。

主机回归测试（不依赖 ESP-IDF，不烧录）：

```sh
cc -std=c11 -I main tests/test_green_detect.c main/ball_detect.c -lm -o test_green_detect
./test_green_detect
```

合成测试覆盖偏绿银灰、荧光黄绿、白底稀释、单点噪声、扁平小目标、底部屏蔽、
断帧重确认、旧轨迹排序，以及红蓝球基本检测。通过不等同于实物检测成功。
