# ESP32-S3 编译指南（task1 工程）

> 适用工程：`Code/task1`（ESP32-S3 + ESP-IDF v5.4.4）
> 目的：让团队每个成员都能在自己机器上编译、烧录，避免"别人编译不过去"。

---

## 1. 为什么别人编译不过去（三个核心原因）

### 1.1 环境是 EIM 安装，不是标准安装

本项目用的 ESP-IDF v5.4.4 是 **Espressif Installation Manager（EIM）** 安装的：

- 工具链全部位于 `C:\Espressif\tools\<tool>\<version>`（cmake、ninja、xtensa-esp-elf 编译器、专用 Python venv）
- **没有 `tools.json` / IDM 元数据**

因此标准激活脚本全部失效：

| 标准脚本 | 结果 |
| --- | --- |
| `C:\esp\v5.4.4\esp-idf\export.ps1` | ❌ 会去搜用户的 `.espressif` 目录，找不到就报错 |
| `export.bat` | ❌ 同样依赖 tools.json，直接失败 |

> 正确入口只有 `Code/task1/activate-idf.ps1`（PowerShell）或 `build.bat`（CMD）。

### 1.2 Git Bash 会被 idf.py 静默拦截（最隐蔽）

`idf.py` 内部有 `MSYSTEM` 环境检查：在 Git Bash / MSYS 环境下会**打印警告后静默退出（exit code 0），根本不编译**。

> 表现：终端显示"成功"，但没有任何编译输出、也没有生成固件。很多人以为编译过了，其实没有。

**解决**：
- 用 PowerShell 走 `activate-idf.ps1`（推荐）
- 或在 Git Bash 用 `env -u MSYSTEM idf.py build`

### 1.3 路径硬编码在本机 C 盘

`activate-idf.ps1` 与 `build.bat` 写死了：

- `C:\esp\v5.4.4\esp-idf`
- `C:\Espressif\tools\...`
- 工具链版本号（如 `esp-14.2.0_20260121`）

换一台机器（即使装了 ESP-IDF）路径不同就会失败。**每个成员的机器必须用 EIM 装 v5.4.4，且路径保持一致。**

## 2. 正确的编译流程

### 方式一：PowerShell（推荐）

```powershell
cd C:\Code\Summer_Course\Code\task1
. .\activate-idf.ps1    # 加载 EIM profile + 设置环境变量
idf.py build            # 编译
idf.py -p COMx flash    # 烧录（COMx 换成实际串口）
idf.py -p COMx monitor  # 串口监视
```

### 方式二：CMD 一键脚本

```cmd
cd C:\Code\Summer_Course\Code\task1
build.bat
```

### 方式三：VS Code ESP-IDF 扩展

在 VS Code 底部点 🔨 编译 / ⚡ 烧录按钮（扩展内部走 EIM 环境）。

## 3. 常见失败对照表

| 症状 | 原因 | 解决 |
| --- | --- | --- |
| `activate-idf.ps1` 报 `required file not found` | 机器没装 EIM 版 IDF | 用 Espressif Installation Manager 装 v5.4.4 |
| `idf.py` 无输出、exit 0 | Git Bash 的 `MSYSTEM` 拦截 | 改用 PowerShell / `env -u MSYSTEM` |
| `WinError 32`（build/log 被占用） | monitor 还开着 | 先停 monitor 再 build |
| CMake 报找不到编译器 | PATH 里没有 `C:\Espressif\tools\...\bin` | 重新 `. activate-idf.ps1`（新终端，不要复用旧环境） |
| `set-target` 报错 | build 目录损坏 | `Remove-Item -Recurse -Force build` 后重跑 |
| 烧录后停在 DOWNLOAD 模式 | 上电时序问题 | 手动按 RESET(EN) 启动 |
| 编译时用了 Anaconda 的 python | `(base)` 环境干扰 | 先 `conda deactivate`，或确认 `activate-idf.ps1` 把 venv 的 python 放最前 |

## 4. 给团队的工作规范

1. **统一用 `activate-idf.ps1`**，不要用 `export.ps1` / `export.bat`
2. **在 PowerShell 里编译**，不要在 Git Bash 里调 `idf.py`
3. 每个成员机器用 **EIM 装 v5.4.4**，路径与仓库脚本保持一致
4. 编译前先 `git pull`；确认没有把 `build/`、`managed_components/` 提交上去（已在 `.gitignore`）
5. **改完代码本地编译通过再提交**，保证 main 永远可构建、可烧录（见 `CONTRIBUTING.md`）

---

## 5. 快速自检：编译环境是否正常

```powershell
cd C:\Code\Summer_Course\Code\task1
. .\activate-idf.ps1
idf.py --version
```

- 正常：输出 `idf.py v5.4.4` 或类似版本号
- 异常：无输出 / 报错 → 按第 3 节对照表排查
